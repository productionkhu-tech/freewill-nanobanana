# NanoBanana 개인판 — 설계

- 날짜: 2026-11-23 · 상태: **승인됨** (2026-11-23 사용자 "이제 만들어야겠지?" — 검토 질문 반영 뒤)
- 본보기: 시댄스 개인판 (`productionkhu-tech/freewill-seedance` HANDOFF §6 '개인판', 규칙 45·46 — 2026-10-21~)
- 이 문서의 "사용자가 정함" 은 대화에서 사용자가 말한 것, "내가 정함" 은 설계자가 채운 것(사용자가 고칠 수 있다)이다.

---

## 1. 무엇을, 왜

회사 밖 사람이 **본인 키 · 본인 돈**으로 쓰는 NanoBanana. 시댄스 개인판과 같은 자리다.
지금 NanoBanana 는 회사 게이트웨이에서 키를 받고(관리자 4자리 승인), 탭마다 팀·프로젝트를 골라야 생성되고, 사용량을 회사로 올린다.
개인판은 이 셋이 없고, 키는 사용자가 프로그램 안에서 넣는다.

사용자가 정함 (2026-11-23 대화):
- 시댄스 개인판처럼 만든다.
- **MCP 는 개인판에 못 붙게** 한다 ("mcp는... 개인판에 못 붙게 해야하긴 해").
- **키는 프로그램 안에서 넣는다** ("키는 뭐 일단 프로그램 들어가서 넣는 거니까").
- **윈도우만** ("mcp 차단하고 윈도우만 ㄱ").
- **EXE 는 둘, 저장소도 나눈다** ("당연히 exe 둘 맞음. 레포도 나눠야함").
  → 내가 읽은 뜻: 시댄스처럼 **소스는 이 저장소 하나**, 개인판 배포는 **새 공개 저장소 `freewill-nanobanana-personal`**(README + 릴리스만).
  시댄스 개인판도 사용자가 "깃허브 분리해서 개인용으로" 라고 한 것을 이 모양으로 만들었다.
- 대화에서 확인한 것: OpenAI 는 본인 키여도 **조직 인증이 필요**하다(gpt-image 계열 403 `organization must be verified`) → 앱이 그때 분명한 안내 + 링크를 띄운다.

받아들인 모양 (대화에서 되짚고 사용자가 받음): 같은 소스의 다른 앱 · 회사 게이트웨이 없음(키 배포·승인·사용량) · 팀·프로젝트 없음 ·
회사 키 거절 · 본인 키는 Gemini(AI Studio) · OpenAI · BytePlus 중 **있는 것만** 넣어도 되고 키 없는 회사의 모델은 메뉴에서 잠김 ·
키는 무료로 확인한 뒤 DPAPI 로 암호화 저장 · 바깥 프로그램(MCP 포함)은 생성 요청을 못 보냄 · 대상은 일반 공개(시댄스 개인판처럼).

## 2. 목표 · 하지 않을 것 · 실패로 보는 것

**목표**
1. 회사 밖 사람이 EXE 하나 받아 → 키 넣고 → 바로 생성. 업데이트는 회사판처럼 껐다 켜면 자동.
2. 회사판과 한 PC 에 같이 깔고 **동시에 켜도** 서로 안 섞인다(포트·데이터·창·업데이트·미니창 자리).
3. 이미지 기능은 회사판과 같다 — 탭·갤러리·레퍼런스·뷰어·미니창·모델 설정·GIF/SVG·프로젝트 저장/열기.
4. 회사판 동작은 **그대로**. 고친 곳은 판(edition) 분기 뒤에만 있다.

**하지 않을 것 (이번 범위 밖)**
- 맥 · MCP/에이전트 경로 · Vertex(개인판 Gemini 는 AI Studio 키 하나) · 비용·사용량 화면 · 팀/프로젝트 · 키 공유 · 코드 서명 · 영어 화면.

**실패로 보는 것 (기술적으로 돌아가도)**
- **회사 키로 개인판이 생성한다** — 회사 돈이 기록 없이 나간다(시댄스 규칙 46 과 같은 이유).
- **개인판이 회사 것을 읽거나 쓴다** — 이 PC 의 환경변수 키, `~/.nanobanana` (금고·출입증·세션·설정), 게이트웨이 사용량·카탈로그.
  (프로젝트 파일은 사람의 작업 파일이라 여기에 넣지 않는다 — 사람이 직접 고른 파일은 열 수 있다, §5.2.)
- **MCP 커넥터·바깥 프로그램이 개인판으로 생성한다.**
- **키가 새는 것** — 디스크 평문, 로그, 프로젝트 파일, 화면 응답(끝 네 글자 말고), 프로바이더 말고 다른 곳으로 원문.
- **회사판이 달라지는 것** — 회사 사용자 화면·커넥터·업데이트가 이번 일로 바뀌면 실패.

## 3. 만드는 방법 (Approaches)

| 방법 | 장단 | 결정 |
|---|---|---|
| **A. 소스 하나, EXE 둘** — 빌드 때 개인판 표시를 EXE 안에 넣는다 | 고치면 두 판에 같이 들어감. 판 분기를 한 곳에서 관리해야 함 | **고름** (사용자 "exe 둘 맞음") |
| B. 저장소를 통째로 복사(fork) | 개인판만 마음대로 바꿀 수 있지만, 매 패치를 두 번 — 한쪽만 고치는 사고. 시댄스도 피함 | 버림 |
| C. EXE 하나에 '개인 모드' 스위치 | 회사 PC 에서 누가 켜면 회사 키·회사 데이터와 섞인다. 업데이트 받는 곳이 달라 어차피 EXE 둘 | 버림 |

배포 저장소는 사용자 말대로 나눈다: 개인판 EXE 는 새 공개 저장소에서만 받는다(§5.6).

## 4. 판(edition) 정하기

- 새 파일 `edition.py` (작게, 다른 모듈을 import 하지 않음): `EDITION` = `"personal"` 또는 `"company"`, `PERSONAL = EDITION == "personal"`.
  - **설치본(frozen)**: `sys._MEIPASS\EDITION` 파일 내용이 정확히 `personal` 이면 개인판, 그 밖(파일 없음 포함)은 회사판.
    **환경변수는 보지 않는다** — 회사 PC 에 누가 심어도 회사 EXE 는 회사판, 개인 EXE 는 개인판.
  - **소스 실행**: `NANOBANANA_EDITION=personal` 이면 개인판 (격리 시험용).
- 빌드: `NanoBananaPersonal.spec` 를 새로 둔다 — `NanoBanana.spec` 과 같고 `EDITION` 데이터 파일 · 이름 `NanoBanana-Personal` · 개인판 아이콘만 다르다.
  같은 src 복사본에서 두 번 빌드한다. 회사 spec 은 `EDITION` 파일을 넣지 않는다.
- 화면은 판을 **서버가 HTML 에 넣어 준 값**으로만 안다(템플릿 치환). 주소 쿼리·localStorage 로는 못 바꾼다.
- 규칙: 개인판 분기는 `edition.PERSONAL` 하나로만 한다(launcher · updater · app · mini_window). 흩어진 이름 비교 금지.

## 5. 설계

### 5.1 다른 앱으로 (한 PC 에 같이 있어도 안 섞이게)

| 항목 | 회사판 (지금 그대로) | 개인판 |
|---|---|---|
| EXE · 릴리스 자산 | `NanoBanana.exe` | `NanoBanana-Personal.exe` (+ `.sha256`) |
| 포트 | 5656 | **35657** (구현 때 정함 2026-11-23 — 처음 정한 5657 은 이 PC 에서 Windows 예약 구간(5576–5675) 안이라 열리지 않았다. Windows 기본 임시 포트 범위(49152~) 밖이고, 범위를 넓힌 PC(이 PC 1024–15000)의 밖이기도 한 값) |
| 한 번만 켜기 잠금 | `NanoBanana-AIImageStudio-SingleInstance-v1` | `NanoBanana-Personal-SingleInstance-v1` |
| 창 제목 · 미니창 제목 | `NanoBanana` · `NanoBanana mini` | `NanoBanana Personal` · `NanoBanana Personal mini` |
| 데이터 폴더 | `~/.nanobanana` | `~/.nanobanana-personal` |
| 프로젝트 폴더 | `문서\NanoBanana JSON` | `문서\NanoBanana Personal JSON` |
| 클립보드·업로드 캐시 | `사진\Screenshots\NanoBanana Clipboard` | `...\NanoBanana Personal Clipboard` |
| 기본 출력 폴더 | `바탕화면\NanoBanana_Output` | `바탕화면\NanoBanana Personal_Output` |
| 미니창 자리 파일 | `mini-dock\nanobanana.json` rank 1 | `mini-dock\nanobanana-personal.json` rank 1.5 |
| 업데이트 받는 곳 | `freewill-nanobanana` | `freewill-nanobanana-personal` |
| 교체 임시 파일 · 로그 | `NanoBanana.new.exe` · `%TEMP%\nanobanana_update.log` | 실행 중인 EXE 이름 기준 · `nanobanana_personal_update.log` |
| 아이콘 | 지금 것 | 같은 그림, 색만 바꾼 것 (내가 정함 — 색은 화면 시안 때 사용자에게) |

- 폴더를 전부 나누는 건 내가 정함. 이유: 시댄스는 백업 폴더를 같이 쓰면 개인판의 빈 기록이 회사 기록을 가져오는 걸 겪었다. 출력 폴더도 두 프로세스가 같은 이름 규칙으로 쓰면
  파일 번호가 겹칠 수 있다(`reserve_filepath` 는 한 프로세스 안에서만 안전).
- 하드코딩된 이름은 launcher 35곳 · updater 18곳 · app 27곳 · mini_window 6곳(2026-11-23 grep, `NanoBanana|nanobanana|5656`). 전부 `edition` 에서 읽게 바꾼다.

### 5.2 회사 것을 안 쓴다

- **게이트웨이 (`nb_gateway`, app.py 25곳)**: 개인판에선 §5.4 의 회사 키 확인 하나 말고는 **한 번도 부르지 않는다** —
  키 받기 · 금고 · 승인 요청/배너 · 평문 정리 · 평문 보고 · 사용량 spool/업로드 · 카탈로그 · Vertex 토큰 전부.
- **이 PC 의 환경변수 키를 읽지 않는다**(`_legacy_env_keys` · `GOOGLE_APPLICATION_CREDENTIALS` 포함). 지우지도 않는다(회사판이 쓴다 — 시댄스도 메모리에서만 지웠다).
- **Vertex 없음**: Gemini 는 AI Studio 클라이언트 하나. Studio↔Vertex 전환은 개인판에서 꺼진다.
- **팀·프로젝트**: 개인판은 자리표시 값을 두지 않는다 — `_billing_usable` 은 늘 참, `_billing_gate` 는 늘 통과(구현 때 정함, 2026-11-23 — 자리표시 id 가 파일에 써질 길 자체가 없어져 회사판 쪽 거절이 필요 없다).
  Status 칸의 팀·프로젝트 단추·창은 숨기고 그 자리에 '내 키' 단추를 둔다. `/api/billing/*` 은 개인판에서 404.
  - 개인판에서 새로 만든 프로젝트 파일은 팀·프로젝트가 비어 있으므로 회사판으로 열면 **고르지 않은 것**으로 읽는다(다시 묻는다).
  - **프로젝트 파일**(내가 정함 — 검토에서 나온 빈칸): 개인판도 사람이 직접 고른 파일은 어디 있든 연다(회사판이 저장한 파일 포함). 개인판이 스스로 회사 폴더를
    열거나 훑지는 않는다(기본 폴더·최근 목록·세션이 다 개인판 것). 연 파일은 그 자리에 저장한다(자동 저장 포함 — 지금과 같음).
    파일에 적힌 **회사 팀·프로젝트 값은 쓰지 않되 지우지도 않는다** — 읽은 그대로 다시 써 둔다. 그래서 회사판이 다시 열면 원래 고른 값이 살아 있다.
    개인판이 새로 만든 파일엔 팀·프로젝트 칸이 비어 있다. 생성은 어느 파일이든 개인 키로만 하므로 회사 돈이 나가지 않는다.
    그 파일의 그림을 보여 주는 것(`_is_path_allowed`)도 지금처럼 열린 프로젝트 기준.
- **에이전트 경로**: `/api/projects` 의 `agent_pid`·`features` 를 개인판에선 비운다. `/api/generate` 에 `pid`·`batch_id`·`check_only` 가 오면 `not_in_personal` 로 거절(§5.5 의 차단 뒤의 두 번째 벽).

### 5.3 내 키

**화면** (정확한 문구·배치는 빌더 몫. 빌드 전에 격리 서버 화면으로 사용자에게 먼저 보여 준다):
```

 (키가 하나도 없을 때 위쪽 띠)  개인판이에요 — 내 키를 넣어야 생성돼요  [키 넣기]

 ┌ 내 키 ───────────────────────────────────────────────┐
 │ Google AI Studio — Gemini 모델                        │
 │   [••••••••••••••••] [확인·저장]   ✓ 확인됨 …a1B2 [지우기] │
 │   키 만드는 곳 ↗ · 이미지 모델은 결제 연결이 필요해요       │
 │ OpenAI — GPT Image                                    │
 │   [                ] [확인·저장]   (없음)                 │
 │   키 만드는 곳 ↗ · 조직 인증이 필요해요 ↗                  │
 │ BytePlus — Seedream                                   │
 │   [••••••••••••••••] [확인·저장]   ✓ 확인됨 …9xQz          │
 │   5.5 는 콘솔에서 활성화가 필요해요 ↗                      │
 │ 키는 이 PC · 이 윈도우 계정에서만 풀리게 암호화해 둬요.        │
 │ 생성 요금은 각 회사가 본인 계정에 청구해요.                   │
 └──────────────────────────────────────────────────────┘
```

**넣기 (`POST /api/personal/keys {provider, key}`, 개인판만 — 회사판은 404)**
1. 앞뒤 공백 제거, 글자인지·길이 확인(규칙 27, `_text_problem` 과 같은 방식).
2. 회사 키인지 확인(§5.4). 회사 키면 거절 + "회사 키는 개인판에 넣을 수 없어요".
3. **무료로 확인** — 생성은 절대 하지 않는다:
   - Gemini: 모델 목록 GET. 이미지 모델이 목록에 있는지도 본다.
   - OpenAI: 모델 목록 GET. (조직 인증은 무료로 못 가른다 → 생성 때 403 이면 안내 + 링크.)
   - BytePlus: 시드림 모델마다 일부러 틀린 size 로 한 번 — **400 = 쓸 수 있음, 404 = 활성화 안 됨·권한 없음, 401 = 틀린 키**
     (CLAUDE.md §6.1 에 적힌 과금 없는 방법). 모델별 결과를 키와 함께 둔다.
4. 결과: 확인됨 → 저장 · 틀린 키(401/403) → **저장 안 함** + 이유 · 인터넷 문제 → 저장하고 "확인 못 함 — 다음에 켤 때 다시 확인" (시댄스와 같음).

**저장**
- `~/.nanobanana-personal\personal_keys.vault` — `nb_gateway` 의 DPAPI 도우미(`_dpapi`·`vault_put`·`vault_get`)를 그대로 쓰되 파일 이름만 다르게.
  **DPAPI 가 안 되면 저장하지 않는다**(평문 대체 없음). 저장 내용: 키 원문 · 확인 시각 · BytePlus 모델별 결과 · 회사 키 확인 여부.
- 화면은 원문을 다시 받지 않는다 — `GET /api/personal/keys` 는 회사별 있음/없음 · 끝 네 글자 · 상태만.
- 로그·이벤트·프로젝트 파일에 키 원문이 들어가는 길이 없어야 한다(시험으로 확인).

**켤 때**
- 금고를 읽어 `_apply_keys(keys, "personal")` (vertex 는 늘 None). 지금 `_apply_keys` 가 받는 모양 `{openai, studio, ark, vertex}` 그대로.
- 금고를 못 열면(로그인 직후 DPAPI 준비 전 · 깨진 파일) 곧바로 '키 없음' 으로 정하지 않고 0.5초마다 최대 30초 다시 연다 — 그 사이 생성·저장은 "키를 불러오는 중"
  (시댄스 26.10.2007~2008 방어: 빈 키 위에 새 키를 저장해 남은 키를 지우지 않게). 끝내 못 열면 다시 넣으라고 띠로 알린다.
- 뒤에서 회사 키 다시 확인(§5.4).

**모델 메뉴**
- 그 회사 키가 없으면 모델이 잠김(회색 + "키 필요", 누르면 내 키 창). BytePlus 에서 404 였던 모델은 "콘솔에서 활성화 필요".
- 잠긴 모델로 생성하면 **요청을 하나도 보내지 않고** 거절.

**생성 중 키 오류**
- 401 류(`_is_auth_error`): 게이트웨이에 다시 묻지 않는다(회사판 `_keys_changed_since` 경로 꺼짐). 그 키를 "거절됨" 으로 표시 + 안내.
- OpenAI 403 `organization must be verified` → "OpenAI 조직 인증이 필요해요" + 인증 페이지 링크.
- Gemini 429 `limit: 0` → "Google 계정에 결제를 연결해야 이미지 모델을 쓸 수 있어요" + 링크.

### 5.4 회사 키 거절

- 회사 키는 지금 게이트웨이에만 있다(현재 키 · `RETIRED_KEY_HASHES` · `TICKET_HASHES` — 모두 워커 시크릿, 공개 저장소에 없음).
  개인판 EXE 에 회사 키 해시를 넣지 않는다(공개 저장소·공개 EXE 라서).
- 워커에 새 길 `POST /personal/check`: 본문 `{p: 키 sha256 의 앞 8글자(hex)}` → 답 `{hashes: [회사 키 sha256 중 그 8글자로 시작하는 것 전부]}`.
  앱이 자기 쪽에서 전체 sha256 을 맞대 본다. **게이트웨이는 키 원문도, 키의 전체 지문도 받지 않는다**(내가 정함 — 공개 앱이라 "회사로 내 키가 가나" 에 떳떳하게 답하려고).
  출입증 없이 받는 길이므로 IP 당 횟수 제한. 비교 대상: OPENAI_KEY · STUDIO_KEY · ARK_KEY 의 sha256 + RETIRED + TICKET.
- 게이트웨이 주소는 회사판과 같은 공개 `gateway_endpoint.txt`(raw GitHub)에서 읽는다.
- **언제**: 저장할 때(맞으면 거절) + **켤 때마다** 뒤에서(맞으면 그 키를 금고에서 지우고 띠로 알림). 저장할 때 못 물어봤으면 "확인 전" 으로 두고 다음 켤 때 묻는다.
  게이트웨이가 안 돼도 개인판 생성은 막지 않는다(확인 전 키도 쓴다 — 시댄스와 같음).
- 워커 배포(`wrangler deploy`)는 바깥에 나가는 일이라 그 단계에서 사용자에게 묻는다.
- **범위는 나노바나나 회사 키만** (사용자 2026-11-23: "시댄스는 너 알빠 아니고"). 받아들인 빈틈: 시댄스 팀 키(BytePlus, 직원 PC 환경변수에 평문)는
  같은 BytePlus 주소를 써서 개인판 BytePlus 칸에 넣으면 시드림이 생성된다 — 이 설계는 막지 않는다. 시댄스 쪽 키·게이트웨이는 묻지도 읽지도 않는다.

### 5.5 MCP · 바깥 프로그램 차단

지금 회사판: 창 토큰(`CSRF_TOKEN`)을 HTML `<meta name="nb-csrf">` 에 넣는다 → 커넥터는 `/` 를 읽어 토큰을 얻고 `POST /api/generate`.
GET 은 토큰 없이 된다.

개인판 (내가 정한 방식):
1. **HTML 에 토큰이 없다** (`index.html`·`viewer.html` 의 메타가 비어 나간다).
2. **launcher 가 만드는 창에만 토큰을 준다** — 창 주소 뒤에 `#nbt=<토큰>` (조각 — HTTP 로 서버에 가지 않는다). 본창 · 뷰어(`open_viewer` 의 `create_window`·`load_url`) ·
   프롬프트 팝업 · 미니창 전부. 창은 전부 launcher 가 만든다.
3. 각 페이지(`index`·`viewer`·`prompt_popup`·`mini`) 맨 앞의 짧은 스크립트가 조각을 읽어 메모리에 두고(`X-NB-Token` 헤더용),
   세션 쿠키 `nbt`(SameSite=Strict, path=/)를 심고, 주소에서 조각을 지운다(`history.replaceState`). 쿠키라서 `<img src>` 같은 GET 도 저절로 토큰을 싣는다.
   새로고침해도 쿠키에서 다시 읽는다. WebView2 는 비공개 모드(실행마다 임시 프로필)라 쿠키는 앱이 끝나면 사라진다.
4. **서버(개인판)**: `/api/*` 는 **GET 포함 전부** 헤더나 쿠키의 토큰이 맞아야 한다. 예외 둘: `/api/version`, 그리고 **두 번째 실행이 본창을 불러오는 요청 하나**
   (지금은 HTML 에서 토큰을 읽어 `/api/mini/toggle` 을 부른다 — 개인판은 토큰 없이 "본창 보이기" 만 하는 전용 길. 창을 보이게 할 뿐 데이터·생성이 없다).
5. §5.2 의 에이전트 필드 거절 · features 비움 (두 번째 벽).
- 회사판은 그대로(메타 토큰, GET 열림) — 커넥터가 계속 된다.
- 한계(받아들임): 같은 윈도우 계정의 프로그램이 일부러 WebView2 임시 프로필이나 프로세스 메모리를 뒤지면 토큰을 찾을 수 있다. 목표는 "커넥터·바깥 프로그램이 평범하게는 못 붙는다".

### 5.7 두 판을 같이 켤 때

- **`_MEI` 청소가 남의 앱을 망가뜨리면 안 된다** (지금도 있는 위험, 개인판으로 흔해진다): `launcher._sweep_stale_mei` 는 자기 것 말고 5분 지난 `_MEI*` 를
  `rmtree(ignore_errors=True)` 한다. 다른 onefile 앱이 돌고 있으면 잠긴 DLL 은 남고 **잠기지 않은 템플릿·static 파일은 지워진다** →
  나중에 켠 판이 먼저 켠 판의 뷰어·미니창 화면을 깨뜨린다. 쓰는 중인 폴더는 건드리지 않게 고친다(예: 폴더 이름 바꾸기가 되는 것만 지움 — 방법은 빌더 몫, 시험으로 증명).

  판을 가려 찾는다 — 제목 앞부분으로는 못 가른다(본창 제목은 화면이 `NanoBanana — 프로젝트명 *` 으로 바꾼다, `static/app.js` 4972행 부근).
  방법은 빌더 몫(예: 창의 프로세스 EXE 경로·판 표시로). (옛 회사 EXE 는 업데이트 전까지 개인판 창을 부를 수 있다 — 회사 잠금이 잡혀 있을 때만이라 드묾, 받아들임.)

## 6. 시험

모든 시험은 격리(규칙 17: `NANOBANANA_DATA_DIR` · `USERPROFILE` · 임시 프로젝트 폴더 · 미니 자리 폴더). EXE 시험 전엔 5656·35657 과 두 EXE 가 안 떠 있는지 확인, 끌 땐 경로로만.

**개인판 (소스, `NANOBANANA_EDITION=personal`, 가짜 프로바이더·가짜 게이트웨이 — 주소 바꾸기는 소스 실행에서만 듣는다)**
1. **회사 것 0건**: 직원 PC 흉내(회사 키 모양의 환경변수 · 가짜 `~/.nanobanana` 금고·출입증) 상태로 켜서 생성까지 — 환경변수·회사 금고 사용 0,
   게이트웨이 요청은 `/personal/check` 말고 0, 사용량 spool 파일 없음, 카탈로그 요청 0.
2. **차단**: HTML 에 토큰 없음 · 토큰 없는 GET/POST `/api/*` → 403 · 조각→쿠키 흐름으로 본창·뷰어·팝업·미니창 다 동작 · `pid`·`batch_id`·`check_only` 거절 · 두 번째 실행의 본창 부르기는 됨.
3. **키**: 맞는 키 저장(금고 파일에 키 글자 없음) · 틀린 키 저장 안 함 · 인터넷 문제면 저장+다음 확인 · 회사 키(앞 8글자 맞음) 거절 · 켤 때 회사 키면 지움 ·
   DPAPI 못 엶 → 다시 시도 → 안내 · 로그·이벤트·프로젝트 파일에 키 원문 0.
4. **잠긴 모델**: 키 없는 회사 모델은 메뉴 잠김, 생성은 요청 0으로 거절 · BytePlus 404 모델 잠김.
5. **프로젝트 파일 교차**: 회사판 파일을 개인판에서 열고 생성·자동 저장 → 회사판으로 다시 열면 원래 팀·프로젝트 그대로(묻지 않음) ·
   개인판이 만든 파일을 회사판으로 열면 팀·프로젝트를 묻는다.

**회사판 회귀** (바뀌면 실패): 릴리스 EXE 스모크(지금 26건) · 미니창 하네스 · 모델 표 대조(`t_models`) · 에이전트 시험 · frozen 회사 EXE 는 `NANOBANANA_EDITION` 을 무시.

**두 EXE 같이**: 포트·잠금·창·데이터 분리 · 각자 두 번째 실행 → 자기 본창 · `_MEI` 청소가 상대를 안 깨뜨림(나중에 켠 쪽이 청소한 뒤 먼저 켠 쪽 뷰어·미니창 열기) · 미니창 셋(시댄스 포함) 쌓기.

**실제 계정**: 키 확인은 무료. 회사 키 거절 경로는 개발 PC 의 실제 회사 키(게이트웨이 시험 신원으로 받음)로 확인한다. 회사 밖 키로 하는 확인·생성은
사용자가 키를 넣어 볼 때, **돈 드는 생성은 사용자 확인 뒤** 회사마다 한 장.
